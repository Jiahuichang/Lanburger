# Art Direction — Lanburger

> **狀態：已核准（2026-11-05）。** 核准後取代 `ART_BIBLE.md`。
> 主要環境參考：`references/lanburger-town.png`。收到與缺少的參考圖見 `references/README.md`。

## 1. 參考圖分析（`references/lanburger-town.png`）

### 1.1 鏡頭與構圖
- **3/4 俯視角**（JRPG 式的抬高俯視）：地面是平的，建築看得到正面和屋頂，角色看得到正面全身。
- 構圖以**中央廣場**為核心：噴水池、Lanburger 雕像與招牌、往北的石階和拱門。四個角落各有一棟主題建築：左上 Language Academy、右上 Burger Bistro、左下 General Store、右下 Racing Track。下方有溪流、小瀑布和木橋。
- 四周用**濃密的樹叢和櫻花樹**包住畫面，自然形成地圖邊界。這個手法可以直接拿來當碰撞邊界。
- 路面是暖色石磚，從廣場放射到每棟建築門口。路線很清楚，玩家一眼就知道能往哪裡走。

### 1.2 色彩與光線
- 整體是**黃昏時分**：上方天空偏暗紫藍，畫面中段亮度中等，彩度控制得好，中間調很豐富。
- **暖光**：路燈、窗戶、燈籠是橘黃色光源（約 `#fde882` → `#e49c29`），帶柔和光暈。
- **冷陰影**：樹叢暗部偏藍綠灰（約 `#1d232e`、`#313e42`），跟暖光形成對比，畫面不會發白、也不刺眼。
- 主要色塊：暖粉棕色石磚（`#ecb49a`、`#c09563`）、酒紅屋頂（`#722f3e`、`#a8464c`）、Bistro 的橘色圓頂（`#f18f30`）、紫色旗幟（`#8f55ab`）、櫻花粉（`#f89eba`、`#d0608f`）、溪水藍（`#61a8df`、`#3369b0`）、木頭棕（`#623d36`、`#955f48`）。
- 上面的色碼是用程式從參考圖抽樣的近似值，實作時會再校正，整理成色票（§4）。

### 1.3 像素質感
- 像素塊**清楚但偏細**：以參考圖的尺寸，一個「美術像素」約 3 個螢幕像素。換算下來，畫面原生解析度大約是高 **310–360 像素**，角色約 **40 像素高**。
- 參考圖本身**不是嚴格的像素網格**：有混合的像素大小、抗鋸齒和柔焦光暈（看起來像 AI 生成的「像素風」圖）。遊戲裡要做成**嚴格對齊網格**的真像素美術，才能維持一致和清晰。
- 描邊：角色用深棕色到近黑色的描邊，環境物件描邊比較淡或不描邊，靠明暗分出形狀。

### 1.4 角色
- **Q 版大頭**：大約 2–2.5 頭身，頭部佔身高將近一半。
- 大眼睛、小嘴、淡淡的腮紅。表情靠眼睛和眉毛。
- 服裝是**現代休閒風**（夾克、帽 T、圍裙、漁夫帽、後背包），不是奇幻盔甲。這點很重要，朋友 NPC 也會保持這個風格。
- 頭上用白色對話氣泡表示狀態（`!`、`…`）。

### 1.5 UI
- **深色半透明面板**（約 `#1c1f29`），細淺色邊框，圓角小。
- 標題用**金黃色**（約 `#e5cf5e`），內文白色，粗圓體無襯線字型（不是像素字型）。
- 左上：頭像、Lv、名字、兩條狀態條（紅 HP `#f34248`、藍 MP `#1e8ef6`）。
- 左側：任務追蹤面板，分 Main Quest / Side Quest 分頁，有勾選框和進度（`0/1`、`0/3`）。
- 右上：一排**木框圖示按鈕**（Quests、Bag、Learn、Collection、Settings），有紅色數字提示。下面是小地圖（標題 Hello Town）。

## 2. 跟目前實作的差異

| 面向 | 目前（Phase 1） | 新方向 | 影響 |
| ---- | --------------- | ------ | ---- |
| 視角 | 橫向捲軸、7 層視差 | 3/4 俯視角、Y 軸排序 | 地圖、鏡頭、物理全部要換 |
| 美術技法 | Canvas2D 執行時繪製的手繪風（柔和曲線、紙紋、霧化） | 嚴格網格的像素美術 | `painter.ts`、`proceduralArt.ts` 不再適用 |
| 色調 | 明亮粉彩（鼠尾草綠、奶油色、淡藍天） | 中低亮度、豐富中間調、黃昏暖光加冷陰影 | `tokens.ts` 的色票要全部重做 |
| 描邊 | 暖棕色、柔和 | 角色用深色描邊，環境以明暗為主 | 規範要改 |
| 主角 | 灰色 PLACEHOLDER 人偶 | Lanburger 漢堡主角 | 新 sprite 和成長變化 |
| UI | 奶油色圓角卡片、可愛風 | 深色面板、金色標題、木框圖示按鈕 | `styles.css` 和 HUD 要重新設計 |
| 光線 | 白天、柔光 | 黃昏、暖色點光源、燈籠會隨進度亮起 | 新的光源層 |
| 地名 | Kingdom of Verdalia、Mossbrook | Hello Town | 地圖資料和文字 |

**保留的原則**：所有顏色、圓角、字型都從 `src/art/tokens.ts` 取得，不在場景或 UI 檔案裡寫死色碼。這條規則不變，只是內容換成新色票。

## 3. 美術製作方式評估

| 方案 | 做法 | 優點 | 缺點 |
| ---- | ---- | ---- | ---- |
| **A. 程式產生的像素美術** | 在原生解析度用程式逐像素畫 tileset 和 sprite（色票索引），執行時或建置時產生 PNG | 沿用目前「美術由程式產生」的流程；不需外部素材；色票保證一致；改得很快 | 地磚、道具、建築可以做到不錯的品質，但人物細節和朋友的相似度有上限，很難完全達到參考圖的精緻度 |
| **B. 外部像素美術師或手繪 PNG** | 依本文件的規格交件，透過 `AssetRegistry.override()` 和 manifest 載入 | 品質最高，最接近參考圖，朋友 NPC 最像 | 需要時間和預算 |
| **C. AI 生圖加人工清理** | 生成概念圖或草稿，再縮到網格、量化到色票、手動修 | 出圖快，適合概念探索 | 很難做出一致的 sprite sheet 和能拼接的 tileset；網格不準；授權和一致性都要再確認 |
| ~~D. 把參考圖直接當背景~~ | — | — | brief 明確不要：碰撞不可靠，也無法互動或擴充 |

**建議：先用 A，同時為 B 留好接口。**
1. 垂直切片先用 A 做出符合本規範的像素地磚、道具、建築和 Lanburger，讓整個流程能玩。
2. 所有美術都經過 manifest 和 `AssetRegistry`。B（或清理後的 C）的 PNG 可以逐張替換，不用改程式。
3. 朋友 NPC 的相似度最好由 B 處理。如果先用 A，就照 §6 的「角色設定卡」流程做，每位朋友都讓你確認。

UI 色（同樣放在 tokens）：`panel #1c1f29`（不透明度約 0.88）、`panelEdge #e6dcad`、`title #e5cf5e`、`text #f4efe4`、`energy`（取代 HP，暖紅橘）、`xp`（取代 MP，藍）、`badge #f34248`、`correct`（綠）、`gentleWrong`（暖橘，答錯永遠不用刺眼的紅）。

**亮度原則**：畫面主體的平均亮度落在中段。最亮的白只留給光源中心、文字和高光。不使用大面積的粉彩或白色。

## 5. 主角 Lanburger（待選方向）

參考圖有兩個「Lanburger」形象：廣場上**戴廚師帽的漢堡吉祥物雕像**，以及 HUD 頭像裡**名叫 Lanburger 的人類男孩**。brief 寫的是「原創、可愛、漢堡主題的主角」，所以請你選一個方向：

| 方向 | 描述 | 成長怎麼表現 |
| ---- | ---- | ------------ |
| **A. 漢堡生物（建議）** | 圓滾滾的漢堡本體：上層麵包是頭（芝麻點點），前面有大眼睛和腮紅；中間的肉排和生菜是身體；短手短腳，戴一條小領巾。跟人類 NPC 一眼就分得出來 | 配料直接疊在身上，整個角色會「長高」（生菜 → 起司 → 番茄……），一看就知道成長了 |
| **B. 漢堡主題的人類** | Q 版人類小孩，戴漢堡帽或穿漢堡帽 T | 用服裝和配件表現，比較不明顯 |

規格（兩個方向都一樣）：
- 單格 32×48 原生像素，角色本體約 36–42 像素高，腳底中心是錨點。
- 4 方向（下、上、左、右；右可以用左鏡像）。動畫：idle（2–4 格）、walk（4–6 格）、talk、celebrate、incorrect（溫和的「咦？」反應）、learn（拿筆記本）。
- 頭像：64×64 原生像素的半身像，6 種表情。

## 6. NPC 與朋友外貌的轉換流程

1. **收照片**：照片放在 `references/private/`，不進 git，見 `references/README.md`。
2. **角色設定卡**（文字，進 repo）：髮型輪廓、髮色、眼型、眼鏡或痣等特徵、招牌服裝、配件、慣用表情、3–6 個從色票選出的專屬顏色、角色定位（例如 Academy 老師）。
3. **你確認設定卡**後才開始畫。
4. **Sprite**：32×48，跟主角同比例和描邊。相似度靠髮型、髮色、眼鏡、服裝和配色，不追求寫實五官。
5. **頭像**：64×64，6 種表情（Neutral、Happy、Surprised、Thinking、Worried、Celebrating）。
6. **檢查**：並排放在參考圖和其他 NPC 旁邊，確認比例、描邊、亮度一致。

照片只當外貌參考，不會直接放進遊戲，也不會描圖。

## 7. UI 方向

- 採用參考圖的結構：深色面板、金色標題、白色內文、木框圖示按鈕、紅色數字提示。
- **狀態條**：HP 換成 **Energy**，MP 換成 **XP**（本遊戲沒有戰鬥）。
- **字型**：UI 用粗圓體無襯線字型（例如 Nunito 或 Fredoka，跟現有字型相近）。學習內容（日文、中文）用清楚的系統字型或 Noto Sans JP/TC 子集，**不用像素字型**，以確保 CJK 好讀。
- UI 文字一律英文。最小字級 14px。按鈕的觸控範圍至少 44×44 CSS px。
- 面板外框可以加一點像素風的角飾，但面板本身保持清晰，讓 HTML UI 在高解析度下依然銳利。
- 小地圖：用同一份地圖資料畫成簡化版，不是另外畫一張圖。

## 8. 光線與氛圍

- 預設時段是**黃昏**，跟參考圖一致。之後可以加入白天、夜晚。
- 做法：色票本身就帶黃昏色溫，加上一層「環境色調」半透明疊色，以及加算混合的光暈 sprite（路燈、窗戶、燈籠）。光暈也會經過像素化，不會出現平滑的漸層。
- **Word Lanterns**：熄滅時是暗色、沒有光暈；點亮時有暖光、光暈，還有一小段點亮動畫。這是最主要的「進度可視化」。
- 環境動畫：噴水池和瀑布的水流、樹葉輕晃、燈火閃爍、櫻花花瓣（數量很少）。可以在 Settings 開啟 reduced motion 關掉。

## 9. 像素技術規格

- **地磚**：16×16 原生像素。
- **原生畫面高度**：約 360 像素（依螢幕整數倍縮放，範圍 300–450），以 nearest-neighbor 放大，不做平滑處理。
- **整數縮放**：桌機 720p → 2 倍，1080p → 3 倍；手機橫向（375 CSS px × DPR 3）→ 3 倍。
- 所有 sprite 的座標都對齊整數像素，鏡頭位置也取整數。
- 貼圖不使用 mipmap，濾鏡用 `NearestFilter`。

## 10. 美術檢查清單（每個階段都要過）

- [ ] 所有顏色都來自 `tokens.ts` 色票，沒有寫死的色碼。
- [ ] 像素對齊網格，沒有混合的像素大小，沒有平滑縮放造成的模糊。
- [ ] 畫面亮度在中段，沒有大面積的粉彩或過亮白色，暖光和冷陰影都在。
- [ ] 角色比例 2–2.5 頭身，描邊一致。
- [ ] UI 文字全部英文，學習語言內容只出現在學習區塊。
- [ ] 文字最小 14px，在 812×375 橫向手機上看得清楚。
- [ ] 沒有通用的示範圖、寫實 3D 素材、emoji 角色或第二套 UI 風格。
